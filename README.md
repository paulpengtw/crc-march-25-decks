# 台灣對外網路流量 degrade 模擬

Reveal.js 6.0.0 簡報, 模擬台灣失去 50% 海纜容量的情境，帶聽眾走過斷纜後 6 小時的逐步崩壞，理解每個故障背後的技術原因與該負責的對象。

語言：zh-TW｜靜態 HTML，無需建置步驟。

## 檔案結構

```
index.html                  ← 主框架，引用外部 Markdown 檔
slides/
  00-cold-open.md           ← Cold Open（2 張）
  01-phase1.md              ← 第一階段：0–5 分鐘（10 張）
  02-phase2.md              ← 第二階段：5–30 分鐘（20 張）
```

投影片內容以 Markdown 撰寫，透過 reveal.js `data-markdown` 屬性在執行時載入。每個 `.md` 檔內以 `---` 分隔各張投影片。

## 投影片結構

### `00-cold-open.md` — Cold Open（2 張）
1. 場景設定：星期二下午，你正在講 LINE 電話，地震斷纜
2. 預告：接下來 6 小時會發生什麼事

### `01-phase1.md` — 第一階段：0–5 分鐘「為什麼我的電話突然斷了？」（10 張）
3. Phase 標題
4. 症狀：LINE 斷線、IG 白畫面、Wi-Fi 滿格但什麼都不動
5. Wi-Fi ≠ 網路：問題不在你家，在海底
6. BGP 科普 1/5：郵局比喻——網路是幾千間郵局互相轉信
7. BGP 科普 2/5：路牌（路由表）與 BGP 的角色
8. BGP 科普 3/5：海纜斷了 = 路斷了，開始廣播
9. BGP 科普 4/5：重算路的混亂期（BGP Reconvergence）
10. BGP 科普 5/5：你的體驗 = 全斷（但 50% 容量還在）
11. LINE 語音 vs 文字：為什麼語音死了但文字可能還活著
12. 施壓對象 → LINE：訴求部署台灣本地通話控制伺服器

### `02-phase2.md` — 第二階段：5–30 分鐘「殭屍網路」（20 張）
13. Phase 標題
14. 症狀：網頁半載、圖片不出來、轉圈圈但訊號滿格
15. 矛盾：BGP 已收斂、路已通——為什麼還是慢？因為路太擠了
16. 壅塞崩潰 1/5：高速公路比喻——10 線道剩 5 線道，車流量沒變
17. 壅塞崩潰 2/5：塞車連鎖反應——丟包 → 重傳 → 更擠 → 惡性循環
18. 壅塞崩潰 3/5：用寄信比喻 TCP 重傳——全台灣同時「再寄一次」= 雪崩
19. 壅塞崩潰 4/5：數字衝擊——50% 容量 → 實際可用僅 15–20%
20. 壅塞崩潰 5/5：日常體驗——100Mbps → 2Mbps，慢到不能用
21. Trombone Effect 轉折：有些伺服器在台灣，為什麼也壞了？
22. Trombone 1/5：便利商店比喻——巷口 7-11，走路 30 秒
23. Trombone 2/5：ISP 強迫你飛東京再飛回來買水
24. Trombone 3/5：為什麼？ISP 之間沒有「牽手」（peering / TPIX）
25. Trombone 4/5：平常你感覺不到（多 20–30ms），海纜出事才致命
26. Trombone 5/5：結果——10 公里外的伺服器，繞了 4,000 公里
27. 施壓對象總覽：ISP、NCC/數位部、立法者
28. 施壓對象 → ISP：公開 peering 政策、在 TPIX 充分互連
29. 施壓對象 → NCC/數位部：稽核路由拓撲，不要只數纜線
30. 施壓對象 → 立法者：立法要求 ISP 對等互連透明化
31. 壓力目標總覽表
32. 階段總結：壅塞崩潰 + Trombone Effect 兩大關鍵
33. 預告 Phase 3：快取正在過期⋯⋯
